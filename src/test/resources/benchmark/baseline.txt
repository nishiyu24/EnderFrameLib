# EnderFrameLib R0 performance baseline
#
# 形式: <document>\t<restyleMs>\t<relayoutMs>\t<displayListMs>\t<scrollStepMs>
# 単位はミリ秒。PerformanceBenchmarkTest が同じ文書を測り、この値と比べる。
# 一致判定は「実測 <= 基準値 * factor + slackMs」。既定は factor=2.0 / slackMs=3.0。
#
# 基準値は 2026-10-24 に Windows / JDK 21 で 3 回測った中央値（初回は 2026-10-20）。
# 2026-10-24 の更新で変わったのは showcase.html だけ（restyle 9.1 → 16.3 / relayout 10.6 → 15.2 /
# displayList 3.3 → 4.8 / scrollStep 12.4 → 17.5）。guidebook.md と large-list はほぼ同じなので、
# マシンの差ではなく 2026-10-20 以降に showcase.html の処理が重くなったもの（原因は未調査）。
# マシンが変わって恒久的に遅い/速い場合は、次のコマンドで更新して差分を確認する:
#   ./gradlew test --tests '*PerformanceBenchmarkTest' -Dbenchmark.update=true
# 一時的な環境差は -Dbenchmark.factor=... / -Dbenchmark.slackMs=... で緩められる。
#
# ベンチは「R1 / R5 の前後で同じ文書がどう変わったか」を見るためのもの。
# 500ms のゆるい上限だけでは、2 倍遅くなっても通ってしまうためこのファイルを持つ。
